# 前端界面设计

本文按 frontend-design skill 的流程编写：先确定主题与受众，再给出设计 token（颜色、字体、布局、原则），然后对照"生成式默认风格"自查并修订，最后才写代码。界面文案一律英文（见 [frontend-plan.md](frontend-plan.md) 的界面语言约定），本文用中文说明。

## 一、主题、受众与首要任务（待确认）

| 项 | 提议 |
|---|---|
| 主题 | 洛杉矶山麓（Altadena / Eaton Canyon）的山火数字孪生 |
| 受众 1：平日 | 电力公司植被管理、县消防、Fire Safe Council 的规划人员：坐在桌前、有时间、要比较方案 |
| 受众 2：危机 | 值班人员与社区协调人：时间紧、要一眼看清"火在哪、几点到哪、谁还没通知到" |
| 受众 3：评委 | 在 Ginsburg Hall 投影上看 5 分钟 demo：远距离、低对比度投影、注意力只有几秒 |
| 首要任务 | **让人一眼看清火会往哪走，以及人能做什么来改变它** |

## 二、现状问题（P1 截至 13d0fd7）

- 所有控制都在 lil-gui 里，像调试工具，不像产品；评委看不出这是给谁用的。
- 左下 HUD 和右下信息面板是开发信息（格子编号、网格尺寸），不是用户关心的内容。
- 只有一种界面状态，dual-use 的"两种生活"在界面上没有体现。
- 信息面板用等宽排版对齐，图例与信息面板是同样的半透明圆角卡片，层级没有区分。

## 三、设计方向：两种生活，两种光线

dual-use 是评分第一项，所以把它变成界面本身的结构：**Plan（平日）和 Respond（危机）是两个模式，切换模式时整个界面的光线随之改变**。

- **Plan**：白天的工作台。浅色、安静、以地形和燃料为主角，工具是"笔刷、预算、方案对比"。
- **Respond**：烟雾笼罩的夜晚。深暖色调、火是唯一的亮色，界面变成按时间排序的事件流和倒计时。

从 Plan 切到 Respond 的那一刻（天色暗下来、火点亮起、侧栏换成事件流）就是 demo 里唯一的编排式动效，也是这个界面最值得记住的地方。其余地方保持克制。

颜色语义直接取自洛杉矶山火的视觉经验：**火是橙色，人的干预是阻燃剂粉红**。2025 年 Palisades、Eaton 火灾后，屋顶和山坡上的 Phos-Chek 粉红色阻燃剂是许多人对那场火最深的视觉记忆。所以界面里凡是"人做的事"（画的防火带、处理方案、按钮、选中状态）都用这种粉红，凡是"火做的事"都用橙色。

## 四、设计 token

### 颜色

| 名称 | Hex | 用途 |
|---|---|---|
| Ash | `#E5E7E1` | Plan 模式界面底色（偏冷的灰绿，像落了灰的纸，不是暖奶油色） |
| Chaparral | `#22322A` | Plan 模式正文与图标；也是植被图层最深一档 |
| Smoke | `#2B231F` | Respond 模式界面底色（被烟遮住的夜空，暖棕而非黑） |
| Ember | `#F26A1B` | 火：燃烧中、火点、蔓延等时线、告警 |
| Retardant | `#D63A73` | 人的干预：处理区、主按钮、选中、焦点环 |
| Marine | `#6F9DBF` | 风与水：风向箭头、风场、不可燃水体 |

辅助色只从以上颜色推导（透明度或明度变化），不再引入新色相。告警分级用 Ember 的三档明度表示：watch 为 Ember 40% 透明度描边，warning 为 Ember 实色，imminent 为 Ember 实色加闪烁边框（尊重 reduced motion 时改为加粗边框）。

色觉无障碍：Ember 和 Retardant 在红绿色盲下可能接近，所以处理区始终同时用**斜线纹理**表示，火始终同时用**发光与动画**表示，不只靠颜色区分。

### 字体

| 角色 | 字体 | 说明 |
|---|---|---|
| 界面与正文 | **Barlow** 400 / 500 / 600 | 以加州公路与路边标志的字形为灵感设计的字体。疏散路线、道路名、社区名天然就是这个字形的语境 |
| 数字与紧凑标签 | **Barlow Semi Condensed** 500 / 600 | 侧栏指标、时间轴刻度；启用 `tabular-nums` |
| 倒计时与关键数字 | **Barlow Condensed** 600 | Respond 模式里"火线距离社区还有多久"的大号 ETA |

同一字族的三种宽度，层级靠宽度和字重区分，不靠换字体。通过 `@fontsource/barlow*` 自托管，断网离线时（PWA）字体仍可用。

字号阶梯（投影可读为前提，最小 13px）：13 / 15 / 18 / 24 / 40 / 72。正文 15px，行高 1.45。不用全大写标签，不用等宽字体排数据，不在标题上方加小号眉标。

### 布局概念

比较了三种布局：

| 方案 | 描述 | 结论 |
|---|---|---|
| A. GIS 仪表盘 | 地图居中，左右各一个固定面板，底部状态栏 | 最常见的默认做法；两侧面板把地形挤窄，投影上主角变小 |
| B. 简报侧栏 + 全幅地形 | 地形全幅铺满；左侧一列随模式变化的叙事侧栏；底部贯通时间与风的控制条；信息跟随选中位置出现在地图上 | **采用** |
| C. 上下分屏 | 上方地形，下方指标与图表 | 地形高度不够，3D 的意义被削弱 |

选择 B 的理由：3D 地形是主角，应该占满屏幕；侧栏读起来像一份按顺序的简报（Plan 时是"预算 → 工具 → 方案对比"，Respond 时是"按时间排列的事件流"），正好对应两种使用者的思考顺序；时间和风是两个模式共有的变量，放在底部贯通条里，切换模式时位置不变。

**对齐与尺寸**

- 侧栏宽 320px，内容左对齐，内边距 20px；数字列右对齐。
- 侧栏、顶栏、底栏是**不透明**的实色面板（Ash 或 Smoke），与地形之间用一条 1px 分隔线，而不是悬浮的半透明卡片。浮在地形上的只有两样：选中位置的信息标签、右下角的图例与风玫瑰。
- 圆角只有两档：浮层 8px，控件 4px；侧栏和栏条不加圆角。
- 窄屏（< 900px）：侧栏变为底部抽屉，可上拉；顶栏模式切换保留。

### 组件清单

| 组件 | 模式 | 说明 |
|---|---|---|
| 顶栏 | 两者 | 产品名、Plan / Respond 分段切换、区域名或 Live / Replay 状态与时钟 |
| 预算条 | Plan | 剩余预算与已用比例，Retardant 色 |
| 处理工具 | Plan | 四种处理手段，各带斜线纹理色块；选中后在地形上画 |
| 方案对比表 | Plan | 三列（You / Greedy / Min-cut）× 四行指标；点击列头在地形上切换方案。用表格而不是三张卡片 |
| 最近社区倒计时 | Respond | 最紧迫的社区名与 ETA，72px |
| 社区列表 | Respond | 按 ETA 排序，告警等级圆点 |
| 外呼统计 | Respond | 已确认 / 未接通 / 需要协助，点击"需要协助"在地形上高亮对应建筑 |
| 事件流 | Respond | 火点、告警、外呼结果，按时间倒序 |
| 底栏 | 两者 | Plan：风向风速与模拟时长、运行；Respond：时间轴（过去为实线、未来预测为虚线、带事件刻度）与当前风况 |
| 地图浮层 | 两者 | 选中位置信息（地名、高程、燃料、到达时间）；右侧工具条、右下角图例、左下角数据署名（见下文"地图浮层的分区"） |
| 调试面板 | — | lil-gui 保留，但只在 URL 带 `?debug` 时出现 |

### 地图浮层的分区（2026-10-17 修订）

原先右下角叠了 4 张卡片（相机、图层、图例、风与显示开关）：
- 在 Plan 模式下约占地图高度的一半，违背"地形是主角"；
- 各卡片宽度不一，左侧边缘参差不齐；
- 显示开关放在风玫瑰的卡片里，和风无关；
- 署名只有 11px，低于 13px 的最小字号；
- 风玫瑰固定朝北，相机转动后箭头方向不对。

修订后按职责分成四处：

| 位置 | 内容 | 说明 |
|---|---|---|
| 右上：工具条（宽 204px，图标 + 文字） | 指南针，视角预设，Orbit / Fly，显示开关 | 指南针的表盘随相机朝向旋转，风箭头始终指向真实风的去向，点击转回正北。视角预设后面标出快捷键 1 / 2 / 3。显示开关（风箭头、烟、房屋提示、卫星火点）打开时图标用 Retardant 粉红、底色带淡粉；房屋提示触到数量上限时显示角标，如 "12/25" |
| 右下：图例卡片（宽 240px，可折叠） | 标题行是图层下拉框，下面是图例 | Plan 默认展开，Respond 默认折叠且图层固定为 Natural；两种模式各自记住折叠状态（浏览器本地存储） |
| 左下：数据署名 | LANDFIRE、Copernicus Sentinel-2、OpenStreetMap | 地图产品的标准位置；13px、低对比度，放不下时省略，悬停看全文 |
| 底部居中：提示条 | 进入飞行模式时的操作说明、飞行速度变化 | 几秒后自动消失，可以关掉；不再撑大卡片 |

窄屏（< 900px）时隐藏图例和署名，工具条只保留图标。

### 设计原则

1. **地形是主角**：界面元素不遮挡地形中部；浮层只放在边缘或贴着选中位置。
2. **颜色有语义**：橙色只属于火，粉红只属于人的干预，蓝色只属于风和水。任何装饰都不能借用这三种颜色。
3. **一处大胆**：唯一的编排式动效是 Plan 到 Respond 的切换（约 1.2 秒：界面底色从 Ash 过渡到 Smoke，天空与光照变暗，火开始发光，侧栏内容交叉淡入）。其余交互只做响应用户操作的即时反馈。
4. **说人话**：文案用使用者的语言（"Fuel break"、"Reached"、"Needs help"），不出现格子编号、网格尺寸这类实现细节；这些移到 `?debug`。
5. **投影优先**：最小字号 13px，正文 15px，关键数字够大；Plan 模式用浅色，因为投影上浅色界面更清楚，深色只留给 Respond 这一段剧情。

## 五、自查：对照生成式默认风格

| 默认特征 | 本方案是否落入 | 处理 |
|---|---|---|
| 暖奶油底 + 衬线标题 + 赤陶色强调 | 初稿 Plan 底色是暖米色 `#EFEBE3` | **已改**为偏冷灰绿的 Ash `#E5E7E1`，来自山火后落灰的地面，与暖奶油拉开距离 |
| 近黑底 + 单一亮色强调 | Respond 是深色，容易落入 | Respond 底色用暖棕 Smoke 而非 `#111`；亮色有两种且各有语义（火 / 人），并且深色只在危机剧情中出现 |
| 报纸式细线、零圆角、密集分栏 | 侧栏用 1px 分隔线 | 保留分隔线，因为它表达"面板与地形的边界"；但不做多栏报纸排版，圆角保留两档 |
| SaaS 卡片套件 | 初稿方案对比是三张卡片 | **已改**为一张三列表格，因为这是同一组指标的横向比较，表格比卡片更准确 |
| 全大写眉标、中点分隔、等宽数据、链接后加箭头 | 现有信息面板用等宽排版 | **改为**定义列表 + Barlow Semi Condensed 的 tabular-nums；顶栏不用中点串联元信息 |
| 01 / 02 / 03 编号 | 无 | Plan 侧栏虽然有先后顺序，但不加编号，用小节标题即可 |

修订后的方案里，Barlow（加州路牌字形）、阻燃剂粉红和"切换模式即换光线"这三点是专属于本项目的选择，换一个题目就不会成立，符合 skill"从主题中寻找独特选择"的要求。

## 六、实现影响

在 [frontend-plan.md](frontend-plan.md) 的阶段之间插入 **P1.5 界面骨架**，后续阶段的 UI 都挂到这套骨架上：

- `web/src/ui/tokens.css`：上述颜色、字号、圆角作为 CSS 变量；`[data-mode="plan"]` 与 `[data-mode="respond"]` 两套取值。
- `web/src/ui/shell.ts`：顶栏、侧栏、底栏、地图浮层的 DOM 骨架与模式切换（同时切换 three 场景的背景色、雾和光照强度）。
- `web/src/ui/planRail.ts`、`respondRail.ts`、`bottomBar.ts`、`mapOverlay.ts`：各区域组件，先用假数据填充。
- 安装 `@fontsource/barlow`、`@fontsource/barlow-semi-condensed`、`@fontsource/barlow-condensed`。
- lil-gui 改为仅在 `?debug` 下加载；现有 HUD 与格子信息移入调试面板。
- 质量底线：键盘可达（模式切换、工具选择、时间轴）、可见焦点环（Retardant 色）、`prefers-reduced-motion` 时模式切换无过渡、窄屏侧栏变底部抽屉。
